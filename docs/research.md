# 幼児向けジグソーパズルアプリ 事前調査レポート

作成日: 2026-10-03 / 対象: HTML で作り、将来 Google Play・App Store に出す

> **この資料の信頼度の見方**
> - ✅ 公式ページまたは複数の情報源で確認できたこと
> - ⚠️ 検索結果の要約のみで確認したこと（申請前に公式で再確認してください）
> - ❓ 今回は確認できなかったこと（調べ方を併記）

## 0. 結論（先に読む部分）

1. **HTML で始める方針は正しい。** ただし「あとでアプリ化する前提」の作り方にしておくと手戻りが少ない（→ 第2章）。
2. **幼児向けにすると、ストアのルールが一番厳しい区分に入る。** 特に重要なのは次の3点。
   - 広告と解析ツールがほぼ使えない（Apple は第三者広告・解析を禁止、Google は認定済みの広告 SDK のみ）。
   - 課金や外部リンクは「保護者ゲート」の内側に置く。
   - 写真機能を付けると、プライバシーポリシーが必須になる。
3. **一番のおすすめ方針: 「広告なし・データ収集なし・端末内で完結」。** ルール対応が最も簡単になり、競合の最大の不満（広告）の解消にもなる。
4. **Google Play は公開までに最短でも約14日かかる。** 個人アカウントは「12人のテスター×14日連続」が必須。早めの準備が必要（→ 第3章）。
5. **競合の「いいところ」と「不満」は、今回は実データを取れなかった。** 調べ方と、現時点で言える仮説を第5章に書いた。

## 2. 「HTML → アプリ」の方法

### 方法の比較

| 方法 | 概要 | Google Play | App Store | 向き不向き |
|---|---|---|---|---|
| PWA（ホーム画面に追加） | ブラウザのまま、アプリ風に | ストアには載らない | ストアには載らない | 家族内の配布・試作には十分 |
| TWA（Trusted Web Activity） | Web サイトを入れた「ほぼ空のアプリ」 | 出せる | **不可** | Android だけなら最軽量。ただしネット接続前提になりやすい |
| **Capacitor**（推奨） | HTML 一式を iOS/Android のアプリに同梱 | 出せる | 出せる | 両ストアに同じ HTML を使える。オフライン動作 |

✅ TWA は「ほぼ空の APK がサイトへのリンクを持つだけ」の仕組み。Capacitor は Web をネイティブ版に包んで両ストアに出せる（[検索結果の要約](https://www.thinktecture.com/en/?p=7342)）。

### 注意点（Apple の「ただの Web サイト」問題）

✅ Apple の審査ガイドライン 4.2 は「**単なる Web サイトの再パッケージを超える機能・UI・コンテンツ**が必要」と定めている（[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)）。
→ 対策: ネットなしで動く（完全オフライン）、効果音・振動・保存機能などを持つ、アプリらしい UI にする。ジグソーパズルはゲームなので通りやすいが、「URL を開くだけ」の作りは避ける。

### 今の HTML 作りで気をつけること（あとで効く）

- **1ファイル完結 or 外部通信なしにする。** 画像・音もアプリ内に同梱（オフライン前提）。
- **指で遊ぶ前提（Pointer Events）で作る。** マウス専用の書き方にしない。
- **画面の向きと大きさに対応。** スマホ縦・タブレット横の両方で遊べるように。
- **端末内保存（localStorage 等）の範囲を決める。** 保存データを増やすほど、プライバシーの説明が必要になる。
- **iPhone の Safari と Android の Chrome の両方で試す。** 音の再生や全画面表示の癖が違う（※実機確認が必要）。

## 3. ストア登録の必要事項

### 3-1. Google Play

| 項目 | 内容 | 信頼度 |
|---|---|---|
| 登録料 | 初回のみ 25 ドル | ⚠️ |
| 本人確認 | 氏名・住所・電話・公的身分証明の提出。個人アカウントでは**住所が公開される場合がある**（要確認） | ⚠️ |
| **クローズドテスト** | **2023年11月13日以降に作った個人アカウントは、12人以上のテスターが14日連続でテストして初めて、本番公開を申請できる。途中で12人を割るとやり直し** | ⚠️（複数の情報源で一致。公式ページは今回開けず） |
| 公開形式 | AAB 形式のファイルで提出 | ⚠️ |
| 対象 API レベル | **2026年8月31日以降、新規アプリは Android 16（API 36）以上が必要**（延長申請は11月1日まで）。すでに期限は過ぎているため、今から作るアプリは最初から API 36 以上が前提 | ⚠️（[検索結果の要約](https://developer.android.com/google/play/requirements/target-sdk?hl=de)） |
| 開発者本人確認 | 2026年からすべての Android アプリに開発者の本人確認が段階的に必須になる。Play 経由の配布者は、すでに Play Console の手続きで満たしている見込み。2026年9月にブラジル・インドネシア・シンガポール・タイで先行し、全世界は2027年以降 | ⚠️（[9to5Google](https://9to5google.com/2025/08/25/android-apps-developer-verification/)） |

**⚠️ 実務上の最大の壁は「12人のテスター」。** 家族・親戚・友人・職場の人に早めに依頼しておくこと。テスターは Google アカウント（Gmail）が必要。

### 3-2. App Store（Apple）

| 項目 | 内容 | 信頼度 |
|---|---|---|
| 年会費 | **99 ドル/年**（約1.4〜1.5万円）。個人・個人事業主は免除の対象外 | ⚠️（[Apple 公式の登録ページ](https://developer.apple.com/programs/enroll/jp) と解説記事） |
| 販売元の表示 | 個人で登録すると、**本名が App Store に販売元として表示される** | ⚠️ |
| 必要なもの | 正式な氏名・メール・電話・住所（私書箱不可） | ⚠️ |
| 開発環境 | アプリのビルドに **Mac と Xcode が必要**（Capacitor を使っても iOS 版には Mac が要る） | ❓ 今回は未確認。一般に知られている条件だが、Apple 公式で確認を。Mac がなければクラウドビルドサービスなどの選択肢もある |
| EU 向け | EU でも配布する場合、事業者（トレーダー）情報の申告が必要。EU 配布を外す選択もできる | ⚠️ |
| テスト | TestFlight で実機テスト（Google のような「12人×14日」の決まりはない） | ❓ |

### 3-3. 費用の目安

- Google Play: 約 25 ドル（1回）
- Apple: 99 ドル/年
- Mac（持っていない場合）: 別途。クラウドビルドの利用も可
- プライバシーポリシー等を置く Web ページ: 無料の範囲（GitHub Pages など）でも可

### 3-4. 見落としやすい現実的な注意

- **副業規定の確認。** 会社員の場合、アプリ公開で収益が出ると副業にあたる可能性がある（無料・無収益でも念のため確認）。
- **税金。** 収益が出た場合は確定申告が必要になる場合がある。
- **サポートの連絡先が必須。** メールアドレスなど。アプリ内とストアページに載せる（Apple 1.5）。
- **権利関係。** イラスト・写真・音源は自作かライセンス確認済みのものだけを使う。キャラクターの無断使用は審査落ちの典型。

## 4. 幼児向けアプリのルール（最も重要）

### 4-1. Apple（✅ 公式ガイドラインで確認）

出典: [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)

- **1.3 キッズカテゴリ**: 外部リンク・購入・気を散らす要素は、**保護者ゲートの内側**にしか置けない。
- **第三者広告・第三者解析は入れない**（例外的に、IDFA や個人を特定できる情報を送らない解析のみ許可）。
- 個人情報・端末情報を第三者に送らない。
- **5.1.4**: 子どもの個人情報（名前・住所・メール・位置・**写真**・動画・描いた絵など）を扱える、または共有できるアプリは、プライバシーポリシーが必須。
- **5.1.1**: プライバシーポリシーへのリンクを App Store Connect とアプリ内の両方に置く。
- キッズカテゴリ以外のアプリは、名前・アイコン・説明で「主な対象は子ども」と示せない。→ **幼児向けと名乗るなら、キッズカテゴリ前提でルールを守る**。
- **3.1.1**: 機能のロック解除（課金）は Apple の課金機能を使う。

### 4-2. Google Play（⚠️ 検索結果の要約）

出典: [AdMob ヘルプ（ファミリー向け広告）](https://support.google.com/admob/answer/6223431)ほか

- 子ども向けアプリは「Designed for Families」のルールに従う。コンテンツ、広告、データ収集、機能、使う技術部品まで対象。
- 広告を出す場合は**Google Play 認定済みの広告 SDK のみ**。
- 広告 ID などの識別子を子どもから送信してはいけない。
- 子どもから個人情報を集める場合は開示する。
- 違反するとアプリが削除される可能性がある。

### 4-3. 法律（⚠️）

- **米国 COPPA（13歳未満）**: 2025年に改正（6月23日施行、遵守期限は2026年4月22日）。顔・声などの生体情報も個人情報に含まれ、広告共有には個別の同意が必要。出典: [Loeb & Loeb](https://www.loeb.com/en/insights/publications/2025/05/childrens-online-privacy-in-2025-the-amended-coppa-rule)
- **日本**: 子ども専用の個人情報ルールは限定的で、基本は個人情報保護法。ただし**ストア側の規約が厳しい**ため、実質的にはストアの基準を満たす設計にすれば足りる見込み。
- **→ 「そもそも個人情報を集めない」設計にすれば、これらの対応コストはほぼゼロになる。**

### 4-4. このアプリへの当てはめ（提案）

| 項目 | 提案 | 理由 |
|---|---|---|
| 広告 | **入れない** | ルールが最も簡単。競合の最大の不満の解消にもなる |
| 解析ツール（Firebase 等） | **入れない** | Apple のキッズカテゴリでほぼ禁止 |
| アカウント登録・ログイン | **作らない** | 個人情報を持たない。アカウント削除機能も不要 |
| 課金 | 当面は無料。やるなら**買い切り**で保護者ゲート付き | 子どもの誤購入を防ぐ |
| 外部リンク（設定・プライバシー） | 保護者ゲートの内側 | Apple 1.3 |
| データ保存 | 端末内のみ | 通信なしにできる |

## 5. 競合アプリの調査

### 5-1. 今回わかったこと

✅ **取得できた範囲が限られる**。ストアのレビューページ（App Store・Google Play・分析サイト）はこの環境から開けなかったため、**レビュー本文の実データは未取得**。以下は検索結果に出た断片的な情報。

**よいとされる特徴**
- **広告なし・ネット不要**（保護者の評価が高い。[Toddler jigsaw puzzle for kids](https://apps.apple.com/us/app/id1080658222)など）
- ピース数を選べる（4〜36ピース。年齢に応じて段階が選べる）
- **ピースが近づくと自動で吸い付く**（指先の細かい操作が苦手でも遊べる）
- ピースが大きく持ちやすい、操作が単純
- 手描き風イラスト、穏やかな音楽
- 写真でパズルを作る機能（「個人的で子どもが夢中になる」という評価）
- 誤課金対策として、購入前に簡単な計算問題を出す

**不満の傾向**
- **広告が頻繁に出る。特にパズル完成の直後に広告が出て、完成した絵をゆっくり眺められない**（保護者が「かわいそう」と書いている例）
- 強引な課金誘導、サブスク前提で、ほとんどのコンテンツが使えない
- アプリの強制終了（クラッシュ）
- 画面設計の不備、アクセシビリティの欠如

### 5-2. 幼児の操作に関する研究知見（⚠️）

出典: [Nielsen Norman Group の子ども向け UX の解説](https://www.nngroup.com/videos/designing-children/)ほか

- **5歳未満はドラッグ&ドロップが苦手**。ドラッグ中に指が画面から離れてしまう。「**タップして選び、置きたい場所をタップ**」の方式のほうが成功しやすい。
- ボタンは大きく（目安 48×48dp 以上）、間隔を空けて誤タップを防ぐ。
- 触ったらすぐ音や動きで反応を返す。
- 3〜5歳は、タップとスワイプを好む。

→ 4歳の甥御さんの場合、**ドラッグ式とタップ式の両方を用意**して、実際に遊ばせて決めるのがよい。

### 5-3. 取り入れたい改善（仮説）

| 優先 | 改善案 | 根拠 |
|---|---|---|
| ★★★ | 広告なし | 最大の不満 |
| ★★★ | 完成後に余韻（拍手・動き・絵のアニメ）を見せ、自動で次に進まない | 完成直後の広告への不満の逆 |
| ★★★ | ピースの吸着（磁石のように近づくと自動で収まる）、吸着範囲は広め | 指先が未発達でも遊べる |
| ★★★ | ピース数を 4 / 6 / 9 / 12 から選べる | 年齢に合わせた段階 |
| ★★ | 間違えたとき叱らない（失敗音を出さない、ヒントの影を表示） | 幼児向け設計の基本 |
| ★★ | 完全オフライン | 保護者の安心 |
| ★★ | ホーム画面に文字をなるべく使わない（絵で選べる） | 4歳はまだ文字が読めない場合が多い |
| ★ | 保護者向け設定（音量・難易度・写真の登録）は保護者ゲートの内側 | Apple 1.3 |

### 5-4. 実データを取るための調べ方

ストアのレビューを自動で取得できなかったので、次のどちらかが現実的です。

1. **手作業で5〜8本のアプリを実際にインストールして遊び、★1〜★2のレビューを読む**。1本あたり15分程度。レビューは「新しい順」と「評価の低い順」に並べ替える。
2. **私に、レビューのスクリーンショットや、コピーした文章を渡してもらう**。こちらで分類して、機能の優先順位表にまとめる。

比較対象のおすすめは、Toddler jigsaw puzzle for kids（OkiPlay）、Puzzle Kids（RV AppStudios）、Kids Jigsaw Learning Puzzles、Kids Puzzle Games 2+ Year Olds、日本語版の「ジグソーパズル海賊」など。このほか、日本のストアで「幼児 パズル」「ジグソーパズル 子供」で上位に出るもの。

## 6. 「自分の好きな写真をパズルにする」機能

### 6-1. 実現のしやすさ

HTML の `<input type="file" accept="image/*">` と Canvas で作れる。**難しくない。**アプリ化したあとも、Capacitor 経由でほぼ同じ形で使える。

### 6-2. 注意点

| 項目 | 内容 |
|---|---|
| **端末の外に送らない** | 写真は端末内で処理し、サーバーに上げない。これが守れれば、プライバシー対応が大幅に簡単になる。 |
| プライバシーポリシー | 写真を扱えるアプリは、Apple 5.1.4 で必須。「写真は端末内のみで処理し、送信・保存しない」と明記する。 |
| アクセス許可 | 端末の写真選択機能（フォトピッカー）を使えば、写真全体へのアクセス許可が不要になる。（⚠️ 実装時に確認） |
| 保護者ゲートの内側 | 子どもが勝手に写真を選べないようにするか、家族の写真を安全に扱えるようにする。 |
| **向きの問題** | スマホで撮った写真は、向きの情報（EXIF）のせいで横倒しになることがある。補正処理が必要。 |
| **画像が大きすぎる問題** | 縮小してから処理する。そうしないと古い端末で固まる。 |
| 切り抜き（トリミング） | 正方形や画面の比率に合わせて切り抜く操作が必要。 |
| 写真の保存 | 前回の写真を残すか。残すなら端末内に保存（保存するデータが増えるので説明が必要）。 |
| 他人の写真 | 本人以外の写真を使う場合の権利は、使う人の責任（利用規約に書く）。 |
| 共有機能を作る場合 | **ここからルールが一気に重くなる**（不適切投稿のフィルタ・通報・ブロック。Apple 1.2）。**最初は共有機能を作らない**ことを強く推奨。 |

## 7. 推奨する進め方

### フェーズ1: HTML 版（今すぐ）
- 4〜12ピースのジグソー、ピース吸着、完成演出、広告なし、オフライン動作。
- 甥御さんに実際に遊んでもらい、タップ方式かドラッグ方式かを決める。

### フェーズ2: 写真機能
- 端末内のみで処理。保護者ゲートの内側に置く。

### フェーズ3: アプリ化の準備
- Capacitor で包む。アイコン・スクリーンショット・説明文・プライバシーポリシーを用意。
- 並行して、Google Play のテスター12人を集める。

### フェーズ4: 申請
- Google Play（先に動き出すと日数が読める）→ App Store。
